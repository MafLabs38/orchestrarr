## R-54-1 | architecture | major | fixed

- **Finding**: a private copy of the inventory against ADR 0002: environments, hosts, nodes, distributions and operating systems in the description.
- **Where**: ADR 0028, `DescriptionScope`.
- **Reason**: fixed: the platform keeps only what a row needs (id, kind `k3s`, environment, the pointer to its version); nodes, hosts, distributions, the upgrade order and the `os` kind are removed; `environments` only point to Portarr's identifiers and are now used (a repository says the environment it deploys to); ADR 0028 says that it amends nothing of ADR 0002.

## R-54-2 | architecture | major | fixed

- **Finding**: Q-10 and Q-03 were settled without being marked.
- **Where**: `docs/SPEC.md`.
- **Reason**: fixed: Q-10 is marked answered by D-78 (confirmed by the maintainer in the chat of 2026-11-12), Q-03 partly.

## R-54-3 | architecture | major | fixed

- **Finding**: the table was built with other inputs for the skip and the approval than for the screen, so a platform row could not be skipped.
- **Where**: `ProblemsEndpoints`, `ProblemHistoryEndpoints`.
- **Reason**: fixed: the skip and the approval build the table with the code and the releases read last, like the screen; a platform row is skipped in a test.

## R-54-4 | architecture | major | fixed

- **Finding**: the code index had no environment dimension: a change would bump every environment at once.
- **Where**: `RepositoryScope`, `DecisionTable`.
- **Reason**: fixed: a repository may say the environment it deploys to; its places are only about the workloads of that environment (tested); ADR 0028 says a change is per environment.

## R-54-5 | architecture | major | fixed

- **Finding**: the forge was read inside the request, one file after the other, with a lock, and nothing told the screens.
- **Where**: `InfrastructureCatalog`.
- **Reason**: fixed: the reading goes on in the background with a time budget, a request waits `FirstWait` (8 s) and is served what was read last, a refresh does not read again before a minute, a failed reading waits too, and the `problems` topic is announced when it ends (tested).

## R-54-6 | quality | major | fixed

- **Finding**: two accepted kinds of files (`terraform`, `ansible-var`) read nothing, and the validation and the reading were two lists.
- **Where**: `VersionParsers`.
- **Reason**: fixed: one table of readers; `terraform` is removed, `ansible-var` becomes `variables`, documented as holding no image.

## R-54-7 | security | medium | fixed

- **Finding**: the diff carried three lines around the change, taken from private files whose content is not searched for secrets.
- **Where**: `VersionPatch`, ADR 0028.
- **Reason**: fixed: the diff is the one line; ADR 0028 says that it is the name of a file that decides, not its content.

## R-54-13 | architecture | major | fixed

- **Finding**: a row's change still bumped every environment at once, and the places of every application that uses the same image.
- **Where**: `DecisionTable`, ADR 0028.
- **Reason**: fixed: an image that runs in more than one environment shows its places and proposes nothing (a change is made for one environment at a time, ADR 0021); the places are the ones of the workloads of the environments of the row; tested. Two applications that run one image are one row (the unit of work is the image, D-21), so the row shows every place that writes it.
