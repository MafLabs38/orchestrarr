## R-53-1 | quality | major | fixed

- **Finding**: the outcome of a history line was read live from the last 2,000 approvals, so an older approval lost it.
- **Where**: `ProblemHistoryEndpoints.Line`, `ProblemsEndpoints.Visible`.
- **Reason**: fixed: the outcome is kept in the history (column `outcome`, schema 7) as soon as it is known (`Conclude`); the live read remains only for a line still in progress, and a line whose approval can no longer be read says *ended*, not *in progress* (tested).

## R-53-2 | architecture | major | fixed

- **Finding**: same finding as R-53-1 from the architecture side.
- **Where**: `HistoryOutcome`, `ProblemHistoryEndpoints`.
- **Reason**: fixed as R-53-1.

## R-53-3 | quality | major | fixed

- **Finding**: the text of a dormant row was the number of days, so the description changed every day and a skip came back the next morning.
- **Where**: `DecisionTable`.
- **Reason**: fixed: the text is `last push <date>`; the number of days is the count, not the text (tested for two different days).

## R-53-4 | architecture | major | fixed

- **Finding**: the dormancy delay, the platform namespace and the Node rule were constants in Core.
- **Where**: `DecisionTable`.
- **Reason**: fixed: a `RelevancePolicy` with defaults, set by the `Relevance` section (`DormantAfterDays` 7 to 3650, `PlatformNamespaces`, `EvenMajorOnlyPackages`); documented in the README; tested.

## R-53-5 | security | low | fixed

- **Finding**: the icon relay accepted any valid name, so any account could make the host call Portarr with its key.
- **Where**: `IconEndpoints`.
- **Reason**: fixed: only an icon that the source named for one of its applications is relayed (tested with an icon the source has but did not name).

## R-53-6 | security | low | declined

- **Finding**: a failed check is excused by its name only.
- **Where**: `GitHubPullRequestSource.ChecksOf`.
- **Reason**: declined: both "CI not run" and "failing" stop at the Runner's validation, so no power is gained, and the list is a setting (`GitHub:ChecksThatNeedSecrets`) that an installation can empty.

## R-53-7 | quality | minor | fixed

- **Finding**: a failed secret-needing check hid a check still pending; a failed answer for an icon was cached for an hour.
- **Where**: `ChecksOf`, `PortarrFleetSource.GetAsync`.
- **Reason**: fixed: pending wins over "not run"; only a 404 is cached (tested).

## R-53-8 | quality | minor | fixed

- **Finding**: interface: the skip button was shown to everyone, the History tab reused the skip hint, empty tabs all said "nothing to decide", the dependency-scan text said "off" for "off or unreadable", the History tab shortened names by hand and cast its filter.
- **Where**: `ProblemTable`, `Decisions`, `History`, `en.json`.
- **Reason**: fixed: skip only for an operator, with the refusal shown; a hint and an empty text per tab; the wording; `shortName`; a type guard (tested for a reader).

## R-53-9 | quality | minor | fixed

- **Finding**: stored enum values parsed with `Enum.Parse`, a state parsed twice and accepted as a number, upper-casing in a loop, a mutable public default list.
- **Where**: `SqliteProblemHistory`, `ProblemHistoryEndpoints`, `ProblemsEndpoints`, `GitHubOptions`.
- **Reason**: fixed: defensive parse, one `IsDefined` check, ordinal-ignore-case sets, an internal read-only default.

## R-53-10 | architecture | minor | declined

- **Finding**: a skip of several rows is not all-or-nothing.
- **Where**: `ProblemHistoryEndpoints`.
- **Reason**: declined: each row is traced then recorded, a failure answers 503 with the rows already skipped shown in the table, and sending the request again skips the rest; a transaction across the trail and the history is not worth its cost.

## R-53-11 | test | medium | fixed

- **Finding**: missing tests: roles and anonymous access to the history and the skip, a state that is not valid, the page size, the icon allow-list, the outcome kept, the dormant text and delay, the options of `Relevance`.
- **Where**: `ProblemsApiTests`, `IconApiTests`, `SqliteProblemHistoryTests`, `DecisionTableTests`, `RelevanceOptionsTests`.
- **Reason**: fixed: added; the other cases listed (the order of precedence of every pair of outcomes, the digest and group ceilings, the icon relay failures) are declined as already covered by the cases that exist or by the code path being the same.
