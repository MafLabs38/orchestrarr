## R-58-12 | architecture | blocker | fixed

- **Finding**: a model decides the next stage: after the first mandate every next mandate comes from the controller's decision, which ADR 0001 did not allow.
- **Where**: `ProblemConductor.Grant`, `ControllerAgent`.
- **Reason**: fixed, and the premise does not hold once the approval is carried to the runner. A: ADR 0001 says "no autonomy of decision, **autonomy of execution**: every work item starts from an explicit operator approval; once approved, Orchestrarr merges and deploys itself, only the steps the operator left ticked". The steps the operator ticked are now **the certificate of the approval authority**: the problem, the repositories, the highest world, the budget and the expiry, signed by an authority that holds the second-factor secret the control plane does not. B: the controller can only choose the order and the moment **inside that envelope**, and the code enforces the envelope at three places that no decision of the controller can reach: `Covers` and `HighestNow` in the conductor (the certificate and the grant read at this crossing bound the world), `ApprovalVerifier.Check` before the mandate is signed, and the **runner's** `MandateVerifier`, which refuses any mandate outside the certificate even when the control plane signed it (`A_runner_refuses_a_mandate_with_no_certificate_or_one_that_does_not_cover_it_even_when_the_control_plane_signed_it`). A controller that answers `grant` for a world above the certificate, another repository, a longer time or a bigger budget produces a mandate that every runner refuses. So the model does not replace the operator's approval: it exercises the autonomy of execution that ADR 0001 gives, inside what the operator approved. ADR 0038 is corrected in the documentation pull request: ADR 0001 is not amended on this point.

## R-58-13 | architecture | major | fixed

- **Finding**: the mandates form a second authorization chain next to ADR 0017's second factor, and the proof of the maintainer's approval does not reach the runner.
- **Where**: `MandateSigning`, `IApprovalCheck`.
- **Reason**: fixed. `ApprovalAuthority` checks the second-factor code with a secret the control plane does not hold (`SecondFactorGuard`, the same guard as ADR 0017, single use per step) and signs an `ApprovalCertificate`. Every mandate names its certificate (`ApprovalId` is in the signed bytes) and carries it; `MandateVerifier` on the runner checks the authority's signature, the validity, that it is the certificate of this mandate and this problem (or rule), and that the mandate falls inside it (no higher world, no other repository, no bigger budget, no later expiry). Tests: the authority refuses a wrong, malformed or reused code and a request that asks for nothing; a widened or foreign-key certificate is refused (`BadSignature`); a runner refuses a mandate signed by the control plane that has no certificate or goes beyond it. The host has no certificate to give yet (the plan service is the next vertical), so no real mandate is issued: that is scope, not a flaw.
