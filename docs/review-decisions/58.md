# Review decisions: pull request 58 (worlds, mandates, the controller and the conductor)

## R-58-1 | quality | major | fixed

- **Finding**: `ConservativeFacts` stated unknown facts in favour (the budget, the diff).
- **Where**: `MissionsServiceCollectionExtensions`.
- **Reason**: fixed: the diff is `bool?` (unknown counts as failing), the budget accounting is declared not built (failing), the pipelines and the artifact are unknown; the demo and the tests bring their own facts.

## R-58-2 | security | high | fixed

- **Finding**: `EffectivePower.Of` skipped a null source, so the plan entry alone gave full power.
- **Where**: `StandingRule.cs`, `ProblemConductor.Start`.
- **Reason**: fixed: a grant that is not given is no power (D-10); a rule is part of the intersection only when the validation comes from one; tested.

## R-58-3 | security | medium | fixed

- **Finding**: the controller prompt wrote the changed file names raw outside the data fence.
- **Where**: `ControllerAgent`.
- **Reason**: fixed: every worker-influenced text in the facts is put on one line.

## R-58-4 | security | medium | fixed

- **Finding**: `Start` and `Open` issued a mandate without checking the global stop.
- **Where**: `ProblemConductor`.
- **Reason**: fixed: the stop is checked at start, at every mandate and at every grant, and a sweep stops what is in progress when it is engaged.

## R-58-5 | security | medium | fixed

- **Finding**: the mandates, the controller's decisions and the ends were not in the audit trail.
- **Where**: `ProblemConductor`.
- **Reason**: fixed: `IMissionAudit` writes problem, mandate, decision, send-back, acceptance, end and revocation events to the audit trail with the reasons.

## R-58-6 | security | medium | fixed

- **Finding**: the controller ran with the host's settings, hooks and working directory.
- **Where**: `ClaudeCliGateway`.
- **Reason**: fixed: `--setting-sources` empty and an empty folder of its own as the working directory, removed after the run.

## R-58-7 | architecture | blocker | fixed

- **Finding**: the first mandate needed no verified approval (a validation was free text).
- **Where**: `ProblemConductor.Start`.
- **Reason**: fixed for what this pull request holds: `IApprovalCheck` must prove the approval; the host answers no until the plan service links a plan entry to an approval, so **no real mandate is issued yet**; the demo has its own check and is never mapped in a deployment.

## R-58-8 | architecture | major | fixed

- **Finding**: read-modify-write with no lock: two overlapping calls could issue two mandates.
- **Where**: `ProblemConductor`.
- **Reason**: fixed: every operation on a problem is serialised; tested with eight parallel starts.

## R-58-9 | architecture | medium | fixed

- **Finding**: an escalation was recorded as a failure and nobody was told.
- **Where**: `ProblemConductor`.
- **Reason**: fixed: `Escalated` is a state of its own (the maintainer's decision), audited; the mail comes with the notifier.

## R-58-10 | architecture | medium | fixed

- **Finding**: expired mandates were never handled.
- **Where**: `ProblemConductor`, host.
- **Reason**: fixed: the sweep ends a mission whose mandate expired without a runner, a problem past its time bound, and everything when the stop is engaged; a timer in the host runs it.

## R-58-11 | architecture | medium | fixed

- **Finding**: the control plane runs Claude Code itself, in every environment.
- **Where**: `ClaudeCliGateway`, `Agents:*`.
- **Reason**: fixed: `Agents:Enabled` is off by default and says in the README that it is the interim for development (the agents belong in a runner's sandbox).

## R-58-12 | architecture | blocker | declined

- **Finding**: a model now decides the next stage: after the first mandate every next mandate comes from the controller's decision, which ADR 0001 and the accepted design did not allow.
- **Where**: `ProblemConductor`, `ControllerAgent`.
- **Reason**: this is the decision the maintainer took in the chat of 2026-11-13 (a controller agent grants each crossing), recorded in ADR 0038 and ADR 0031 of the documentation pull request, which amends ADR 0001. It cannot be fixed in code: it is the design. It needs the maintainer's acceptance of that ADR; nothing real runs on it until then (R-58-7). A serious finding that is not fixed here.

## R-58-13 | architecture | major | declined

- **Finding**: the mandates form a second authorization chain parallel to the accepted one (the second factor checked by the runner, ADR 0017), and the proof of the maintainer's approval does not reach the runner.
- **Where**: `MandateSigning`.
- **Reason**: the proof carried to the runner is ADR 0031 point 7, decided in the documentation pull request and not built in this one (the plan service and the runner's verification are the next verticals). Until it is built, no real mandate is issued (R-58-7). It needs the maintainer's acceptance that this is the order of work.

- **Reason**: the pull request is based on the documentation pull request (56), which carries the ADRs 0030 to 0038, FUNCTIONAL, ARCHITECTURE and USE-CASES; it targets develop when that one is merged.
