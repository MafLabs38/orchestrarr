# Review decisions: pull request 83 (a broken pipeline control is mended, never taken out; cases 08 and 14)

## R-83-1 | security | medium | fixed

- **Finding**: An empty path filter, or one made of negations only, was measured as dead, while the forge may read it as covering everything; narrowing it to one file would have passed as a mend.
- **Where**: `WorkflowStructure.PathFilter.IsPlain`
- **Reason**: fixed: such a filter is not measured, so any change of it is refused; tested.

## R-83-2 | security | medium | fixed

- **Finding**: The controller was told that replacing a version that does not exist or is end-of-life is a mend, with nothing but the worker's word for it.
- **Where**: `ControllerAgent` (the second control), `ChangeProof`
- **Reason**: fixed: an action is replaced only by the same action at another version; the claim is granted only when the failure in the facts shows it or it is public knowledge the controller is sure of, never on the worker's word. The facts now say why each red pipeline failed (the job, the failed step and the first error the forge annotated: `IPipelineFailures`), read on the forge; tested.

## R-83-3 | test | medium | declined

- **Finding**: No test passes a tree through the handover endpoint, nor a captured controller input in the later worlds.
- **Where**: `MissionRunnerEndpoints`, `MissionDriver`
- **Reason**: declined: the rule, the helper that drops added files and the justification pick are unit-tested, the endpoint passes the list in one expression, and the replays of case 08 run the whole path on the forge.

## R-83-4 | quality | minor | declined

- **Finding**: Minor points of the first round (resource bounds of the measurement, wording, test layout).
- **Where**: several
- **Reason**: declined as minor; the patterns are bounded in count and length and each match has a timeout.

## R-83-5 | spec | major | fixed

- **Finding**: ADR 0057 and D-111 did not say that the facts now carry why each red pipeline failed, nor the evidence rule for a version claim and the same-action rule.
- **Where**: ADR 0057 point 5, SPEC D-111
- **Reason**: fixed: both say it.

## R-83-6 | security | medium | declined

- **Finding**: The failure text that the controller may take as evidence is written by the repository (a step can print an error annotation).
- **Where**: `GitHubPullRequestFacts.WhyItFailedAsync`, `ControllerAgent`
- **Reason**: declined: it is the output of the runs of the default branch (the maintainer's code, not the agent's change), given as data; it can only support replacing a version of the same action or of a runtime, which the controller still judges and which checks as much as before; a forged message cannot make a check run less.

## R-83-7 | security | major | fixed

- **Finding**: The mend of a dead path filter applied to every trigger, `pull_request_target` included, so a dormant trigger that runs with the base's credentials could be woken.
- **Where**: `WorkflowStructure.LostTrigger`
- **Reason**: fixed: a filter change of a trigger that runs with the base's credentials is refused; tested.

## R-83-8 | security | medium | fixed

- **Finding**: "Another version of the same action" lived only in the prompts; the check of the code did not read `uses`.
- **Where**: `WorkflowStructure`
- **Reason**: fixed: a change that takes an action out of an existing workflow and brings another in is refused (`SwappedAction`); another version of the same action passes; tested.
