## R-56-67 | security | high | fixed

- **Finding**: merging into the release branch brings the agent's merged code (build scripts, test helpers, package hooks) into a pipeline that holds the deployment secret.
- **Where**: ADR 0035.
- **Reason**: fixed by mechanisms, not by a rule that the pipeline never deploys (the maintainer, 2026-11-15: no fixed release rule, the agent judges). The Git-world crossing is refused when the merge may deploy (or is not known not to) and the approval stops before the release world; when it may deploy and the approval reaches the release world, a change that touches files the pipeline executes is escalated to the maintainer, so agent code that could reach the deployment secrets without having been proved is never merged on the controller's word alone; a release needs the artifact proved in staging by its digest. The facts come from the forge, unknown counts as failing, and the code is in the first pull request of the code (`PreconditionFailure.MergeMayDeployBeyondApproval`, `ExecutedFilesTouchedWhereMergeDeploys`, tested).
