# Review decisions: pull request 60 (the act gateway merges and the runner deploys)

## R-60-1 | security | medium | fixed

- **Finding**: The merge used `GitHub:Token`, the token of every reader, and nothing limited it to the test bed.
- **Where**: `SandboxMissions`
- **Reason**: fixed: the gateway merges with `Missions:SandboxMergeToken`, with no fallback, and only on the repositories of `Missions:SandboxMergeRepositories`; without both it merges nothing; tested.

## R-60-2 | architecture | major | fixed

- **Finding**: The same: one token for reading and merging, and no list of repositories.
- **Where**: `SandboxMissions`, README
- **Reason**: fixed with the previous entry; the README and the ADR say that `GitHub:Token` stays read-only.

## R-60-3 | architecture | major | fixed

- **Finding**: The act itself was not in the audit trail, only its authorisation.
- **Where**: `MissionActEndpoints`
- **Reason**: fixed: `act.performed` is written after the merge with the commit it made or the refusal of the forge; the deployment is written when the release dossier arrives, as what the runner reported; tested.

## R-60-4 | architecture | medium | fixed

- **Finding**: A pull request found merged was reported as the gateway's own, at whatever head.
- **Where**: `MissionActEndpoints`
- **Reason**: fixed: found merged at another head than the approved one is refused, at the approved head it is reported and written down as found already merged; the dossier no longer says that the gateway merged it.

## R-60-5 | architecture | medium | declined

- **Finding**: The way back is declared known by the sandbox before the deployment, the previous version being read by the runner after the authorisation.
- **Where**: `SandboxFacts`
- **Reason**: declined for the test bed: declared in the startup notice and in ADR 0043 8(c); read before the authorisation is the vertical that gives the control plane a record of what is deployed.

## R-60-6 | architecture | medium | fixed

- **Finding**: Two repositories can land on one port.
- **Where**: `ReleaseWorld`
- **Reason**: fixed as far as detection: a port held by another application stops the deployment with a message; not resolved (ADR 0043 8(e)).

## R-60-7 | architecture | medium | fixed

- **Finding**: Departures from ARCHITECTURE (the gateway on the control plane, the tree as an unsigned string) were not declared.
- **Where**: ADR 0043
- **Reason**: fixed: ADR 0043 point 8 lists them with what closes them.

## R-60-8 | architecture | medium | fixed

- **Finding**: The status line, the roadmap row and the stage paragraphs still said that nothing merges.
- **Where**: `README.md`, `CLAUDE.md`, `docs/SPEC.md`
- **Reason**: fixed.

## R-60-9 | security | medium | deferred

- **Finding**: The tree that was proved in staging is a string written by the runner, so the release precondition rests on the worker's word.
- **Where**: `StagingProof`, `SandboxFacts`
- **Reason**: deferred to the vertical that signs the proof with the staging runner's key and reads it from the delivery; written in ADR 0043 8(b). The merge result is compared with it, and the forge's own protections still apply.

## R-60-10 | security | medium | fixed

- **Finding**: A compose file of the repository could mount the host or join its network when deployed.
- **Where**: `ReleaseWorld`
- **Reason**: fixed: a compose file is not deployed; ADR 0043 8(g).

## R-60-11 | quality | major | fixed

- **Finding**: A sent-back mission whose rework had been handed out blocked the claims of its world.
- **Where**: `MissionRunnerEndpoints`
- **Reason**: fixed: an offered rework is filtered out before the choice and consumed only for the mission that is returned; tested with a second repository.

## R-60-12 | quality | major | fixed

- **Finding**: Two owners with one repository name shared a container and a clone.
- **Where**: `ReleaseWorld`
- **Reason**: fixed: the name is the owner and the repository; tested.

## R-60-13 | quality | major | fixed

- **Finding**: The wait after the merge shared the deadline of the wait before it.
- **Where**: `GitWorld`
- **Reason**: fixed: each wait has its own time.

## R-60-14 | quality | major | fixed

- **Finding**: The port function depended on the endianness of the machine.
- **Where**: `DeploymentPort`
- **Reason**: fixed: big-endian whatever the machine; the base is validated on both sides.

## R-60-15 | quality | medium | fixed

- **Finding**: The evidence prefixes were bare strings on both sides; the options of the runner were not range-checked; the summaries of `ForContents` and `WithToken` were mixed.
- **Where**: `MissionEvidence`, `MissionRunnerOptions`, `GitHubOptions`
- **Reason**: fixed: the prefixes are in Core, the options are checked, the summaries are put right.

## R-60-16 | quality | medium | declined

- **Finding**: The rework state is not bounded and is lost at a restart.
- **Where**: `MissionProgress`
- **Reason**: declined: in memory by design for the test bed, one lock and one dictionary now, and the dossier is the record.

## R-60-17 | architecture | major | fixed

- **Finding**: `IgnoredChecks` skipped a check by its name alone, so a job that a pull request names "Dependabot" would not be judged.
- **Where**: `GitHubPullRequestFacts`
- **Reason**: fixed: a check is ignored only if its name and the application that made it are both in the settings; tested.

## R-60-18 | architecture | medium | fixed

- **Finding**: `SandboxMaxWorld` defaulted to the release world.
- **Where**: `MissionsOptions`
- **Reason**: fixed: the default stays the Git world; the test-bed configuration sets `Release`, and the pull request says so.

## R-60-19 | architecture | medium | declined

- **Finding**: The staging merge is made on the default branch, not on the base of the pull request.
- **Where**: `StagingProof`
- **Reason**: declined for now and written in ADR 0043 (a pull request whose base is not the default branch is not handled): the claim carries the base in a later vertical.

## R-60-20 | security | medium | fixed

- **Finding**: The README and the ADR said that `GitHub:Token` merges.
- **Where**: `README.md`, ADR 0043
- **Reason**: fixed.

## R-60-21 | test | medium | fixed

- **Finding**: A polling loop with real delays waited for a mission that a pass of the driver gives at once.
- **Where**: `MissionWorldsApiTests`
- **Reason**: fixed: no delay.

## R-60-22 | test | medium | declined

- **Finding**: One test builds three fact sources.
- **Where**: `MissionRunnerApiTests`
- **Reason**: declined: the three cases share one setup; the null health assertion of the moved case now has a health source to be null for a reason.
