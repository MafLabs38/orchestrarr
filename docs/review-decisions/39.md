# Review decisions: pull request 39

Real validation, repair by an agent on paper, live screens and a readable table. Every finding of the five agents of the first round (head `b2f5dd2`) was checked in the code. **Fixed** (not entered below, one line each in the pull request's *Review* section): the host `git` that read a folder a container could write (critical), the token and the pull request's code in one container, the pull request's own `CLAUDE.md` and settings steering the agent, the marker that the output could close, the protected paths that did not cover nested files or test configuration, the repair checked in a dirty folder, the stringly-typed "repaired", the live sender that could hide an outcome, the notices of ADR numbers, the documents that said "dry run, starts nothing", and the tests that were asked for.

## R-39-1 | architecture | major | declined

- **Finding**: the repair is classed `ChangesNothing`, so the code of the second factor can be off while an agent runs with the subscription token and open network egress (D-28); either keep the code asked for, or give the agent no shell and restrict its egress to the model's API.
- **Where**: `RepairPullRequestRunner.ChangesNothing`, ADR 0023 §5 and ADR 0024 §2 and §4.
- **Reason**: the exposure that the finding describes is fixed: the agent has no shell (the executor runs the steps), so the code of a pull request never runs beside the token; it cannot read outside the work folder, it does not see the pull request's own instructions, and the token is masked in every line of the trace. What is left is the open egress of the agent's container (nothing in it can use it: no network tool, no shell) and the relaxation of the code for the sandbox. Keeping the code asked for would bring back the second factor at every click in the sandbox, which the maintainer asked to avoid for tests; restricting the egress needs a proxy or a network policy that does not exist yet and is to be built before the repair touches anything private. The relaxation is only possible where the host allows it (never in Production). The ADR 0024 records the exception to D-28.
- **Approved**: to be given by the maintainer in a comment of this pull request ("OK to decline R-39-1")

## R-39-2 | architecture | minor | declined

- **Finding**: the verdicts of the workshop come from the newest 500 results of the whole queue, so an old commit falls out of the window and a "patch ready" row goes back to "Repair".
- **Where**: `ProblemsEndpoints.WorkshopWindow`.
- **Reason**: bounded on purpose, since the query runs on every read of the table; it is a named constant with its reason, and ADR 0024 records the limit. A per-commit store (the latest verdict per repository, pull request and commit, with an index) comes with a fleet large enough to need it.

## R-39-3 | quality | minor | declined

- **Finding**: glyphs (`✦`, `▲`, `▼`) are written in the components instead of coming from the icon registry.
- **Where**: `frontend/src/Decisions/ProblemTable.tsx`.
- **Reason**: they are text marks of a verdict and of a sort direction, read by the page as text (the sort header has its own accessible name); an icon component would add nothing to a screen reader.

## R-39-4 | quality | minor | declined

- **Finding**: `Live.cs` holds four small types; `LiveHub.Path` and `AgentTranscript.Path` shadow `System.IO.Path`; `Answer`/`AnswerOf` and `Kill` names.
- **Where**: `Live/Live.cs`, `AgentTranscript.cs`, `ExecutorEndpoints.cs`.
- **Reason**: naming and file layout, no behaviour; the four types are one idea (the channel) and are tiny.

## R-39-5 | test | minor | declined

- **Finding**: the cut assertion of `AgentTranscriptTests` pins an exact length.
- **Where**: `AgentTranscriptTests`.
- **Reason**: the length is the documented bound of what a trace line keeps (300 characters and a mark); pinning it is the point of the test.

## R-39-6 | test | minor | declined

- **Finding**: the table tests read a whole row as one text and pin the sort order of a column.
- **Where**: `Decisions.test.tsx`.
- **Reason**: a row read as a line is what the operator reads; a change of the order of the columns should break these tests. The sort test pins the numbers, which are the stable language of the table.

## R-39-7 | test | medium | declined

- **Finding**: nothing tests that each executor route announces (claim, lines, end) and only on success.
- **Where**: `ExecutorEndpoints`.
- **Reason**: the rules of announcing (not on a read, a refusal, the executor routes or the sign-in) and the registry's change detection are now tested, and the executor routes are exercised end to end by the real executor in `ExecutorApiTests`; the three calls are two lines each on the same notifier.
