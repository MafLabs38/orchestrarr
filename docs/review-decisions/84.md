# Review decisions: pull request 84 (a release that fails after its merge is fixed forward; CASE-06)

## R-84-1 | security | medium | fixed

- **Finding**: The base image check could be passed around by an `ARG` that names the image, a tab after `FROM`, or a lowercase `dockerfile`.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed: the default of an `ARG` that names an image counts as an image, a `FROM` is read whatever the space after it, and the file name is matched in any case; tested.

## R-84-2 | quality | major | fixed

- **Finding**: Any `ARG` default with a `/` or `:` (a URL, a path) was read as a base image, so a legitimate change of such an argument would be refused.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed: only the images that a `FROM` uses count, each resolved against the `ARG` defaults of the whole file read before and after the change; tested.

## R-84-3 | security | medium | fixed

- **Finding**: `FROM ${BASE:-node:20}` and `ARG BASE=node` with `FROM ${BASE}` still swapped a base image unseen.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed: the whole container file is read before and after the change (`RepairBase.WorkflowsAsync` now reads container files), every `FROM` is resolved (`${X}`, `$X`, `${X:-d}`, `${X:+d}`), and a `FROM` that cannot be resolved in the file is refused; tested.

## R-84-4 | security | medium | fixed

- **Finding**: ARGs declared after the first `FROM` were read as if a `FROM` saw them; a stage alias defined later hid an image; the check fell back to the patch when the whole file was not read; a dead stage kept the old image while a new one came in; a new image was allowed when no old one disappeared.
- **Where**: `ChangePolicy.SwappedBaseImage`, `RepairBase.WorkflowsAsync`
- **Reason**: fixed: the rule is strict and fails closed. A container file never gets an image it did not have (only a newer tag of one it had); a file not read whole before and after is refused; only the ARGs before the first `FROM` count; a stage is one defined by an earlier `FROM`; tested.

## R-84-5 | quality | major | fixed

- **Finding**: The base image guard failed open when the whole file was not available.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed with R-84-4: it fails closed.

## R-84-6 | security | medium | fixed

- **Finding**: `ARG` with several pairs on one line, continued lines and quoted values were skipped, so a later default could change the image without the check seeing it.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed: an `ARG` is read word by word after continued lines are joined, each pair applied in order; a word that cannot be read makes its names unknown, and an image that cannot be resolved is refused; a changed escape directive is refused; tested.

## R-84-7 | security | medium | declined

- **Finding**: A `# syntax=` frontend, `COPY --from=<image>` or `RUN --mount=from=<image>` can bring in an image that no `FROM` names.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: the check holds the maintainer's rule of proportion (the image an application runs on is not replaced, ADR 0055), not the containment of a build: a free agent's `RUN` line can already fetch and run anything, so a frontend or a `--from` adds no power; what a build runs is judged by the controller on the patch, and a build is contained by the isolated staging machine. ADR 0058 point 3 says so.

## R-84-8 | architecture | major | fixed

- **Finding**: "a container file never gets an image it did not have" was a product rule not attributed to the maintainer, and it refused an ordinary build stage.
- **Where**: `ChangePolicy.SwappedBaseImage`, ADR 0058 point 3, D-112
- **Reason**: fixed: the check now holds only the maintainer's rule of ADR 0055 (a runtime replaced is his decision): the image of the final stage is raised, never replaced; a new build stage passes to the controller; a refusal is an open point that the controller escalates. ADR 0058 and D-112 cite ADR 0055.

## R-84-9 | security | medium | fixed

- **Finding**: A comment or blank line inside a continued instruction, or a heredoc body, could make the check read another final `FROM` than the one Docker builds.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed: comment and blank lines are left out before continued lines are joined, as Docker does, and a container file that holds a heredoc is refused (a person decides); the three files of the finding are tests.
