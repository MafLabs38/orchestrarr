# Review decisions: pull request 84 (a release that fails after its merge is fixed forward; CASE-06)

## R-84-1 | security | medium | fixed

- **Finding**: The base image check could be passed around by an `ARG` that names the image, a tab after `FROM`, or a lowercase `dockerfile`.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed: the default of an `ARG` that names an image counts as an image, a `FROM` is read whatever the space after it, and the file name is matched in any case; tested.

## R-84-2 | quality | major | fixed

- **Finding**: Any `ARG` default with a `/` or `:` (a URL, a path) was read as a base image, so a legitimate change of such an argument would be refused.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed: only the images that a `FROM` uses count, each resolved against the `ARG` defaults of the whole file read before and after the change; tested.

## R-84-3 | security | medium | fixed

- **Finding**: `FROM ${BASE:-node:20}` and `ARG BASE=node` with `FROM ${BASE}` still swapped a base image unseen.
- **Where**: `ChangePolicy.SwappedBaseImage`
- **Reason**: fixed: the whole container file is read before and after the change (`RepairBase.WorkflowsAsync` now reads container files), every `FROM` is resolved (`${X}`, `$X`, `${X:-d}`, `${X:+d}`), and a `FROM` that cannot be resolved in the file is refused; tested.
