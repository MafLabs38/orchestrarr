# 0028 — The description is the perimeter, and the version lives in the code

- **Status**: proposed (asked for by the maintainer on 2026-11-12; accepted when the pull request that carries it is merged)
- **Date**: 2026-11-12
- **Spec**: D-78, D-79, D-80, D-81 (extends ADR 0020 and ADR 0027)

## Context

The audit of the table ([ADR 0027](0027-the-table-shows-what-can-be-decided-by-application-and-keeps-what-was-decided.md)) showed that a new version of an image is only half of the work: the version of an image is written somewhere in code (a manifest, a kustomization, a Terraform file, a compose file, a variable of an inventory), and a redeployment from that code brings the old version back. A row that says "bump this tag" is useless if nobody knows which file holds the tag. The code that holds the versions is spread over several repositories, some owned by the maintainer, some of which describe third-party software, and some of which are not on the forge at all.

The maintainer asked for the same state of mind as Portarr: **one YAML description says what is maintained, and the product works inside it, with no magic.** Extending the perimeter, or reducing it, is editing that file (by hand, through the MCP or through an editor, later). A repository the maintainer does not care about is not in the file, so it is never read.

## Decision

1. **The description is the only entry** (extends [ADR 0020](0020-applications-are-described-in-a-private-configuration-repository.md)). It is a YAML file (JSON is YAML, so the existing file still reads) named by `Description:File` (`Applications:File` is still read). It has four sections: `environments` (identifiers of Portarr, only the ones the perimeter refers to), `platforms`, `repositories`, and `applications` (as before, with a source that may be an object: `{ repository: … }` or `{ image: … }`, and `third-party` written either way). A mistake in it stops the start and says where.
2. **`repositories` is the perimeter of the code.** Each entry names a repository, the **kind** of files it holds (`kubernetes`, `kustomize`, `compose`, `terraform-docker`, and `variables` for a file of variables that a platform points to), the **paths** (globs) that are read, and, when the repository deploys to one environment, that `environment`: a change is per environment, never one that bumps every environment at once. Orchestrarr reads no other code. The findings and the pull requests it lists still come from its sources and are not filtered by the description yet. A file whose **name** says that it holds a secret (`*.enc.*`, `*.tfstate*`, `*.tfvars*`, `.env*`, keys) is never read, whatever a path says; the content of a file is not searched for secrets, so the change that is shown is the one line, with nothing around it.
3. **Where a version is written is found by a deterministic reader, line by line, inside that perimeter**: an `image:` line, a `newTag`, a string given to a `docker_image`, a value of a variable file. No heuristic, no crawling, no model. A line that carries Flux's marker is Flux's, and Orchestrarr does not change it.
4. **A row about an image says what it found.** (The description of a work item is the one under its own identifier, else the one of the application that Portarr says it is; when several applications with different policies share it, there is none and nothing is guessed.) Found where: the file and the line, and (when the version is known and not a major one) the version a change would write; an outdated image goes to the latest, a floating one (`latest`, no tag) is **pinned to the version that runs**, which changes nothing that is deployed and makes a later update visible. Found nowhere: the row is in *To configure* ("add the repository that deploys it to the description, or leave it out"). Written by Flux: nothing to do. Pinned by a digest: the place is shown and no change is proposed, the pin is a decision. A repository of the description that could not be read: the image is not said to be written nowhere. Written as one version while another runs: the row says so and proposes nothing. A major version is a change to plan: it shows the place, not a version. An image that runs in several environments shows its places and proposes nothing: a change is made for one environment at a time, qualified and then promoted (ADR 0021).
5. **The change is shown, never applied.** `GET /api/v1/problems/change?id=` computes the exact change of one line and its unified diff from the text that was read; the version written must be a tag of the OCI grammar (`[A-Za-z0-9_][A-Za-z0-9_.-]*`, 128 characters at most), so that a value from a registry cannot change the structure of a file. The change of a platform is not computed: its row says the versions, and the procedure is a person's. Orchestrarr still holds no write power: applying it is the maintainer's, and later the Runner's under its own rights (a separate vertical).
6. **A platform is not an image** (`platforms`, only `k3s` for now). The version of K3s is a variable of the code of the cluster (`k3s_version`). The table says when a patch of the same minor exists, and when the **next** minor exists (Kubernetes is upgraded one minor at a time), read from the public release channels of K3s (`Platforms:K3sChannelsUrl`, off unless set). These rows are information and describe the upgrade: described in words (workers first, a snapshot before, a way back, one minor at a time); no field of the row carries the order. A platform is never upgraded by itself. Platform rows are the one place where Orchestrarr itself says that something is outdated, from the code and a public feed, because Portarr does not report the version of the platform today; if it does, these rows move to its findings. Operating systems are not in the description yet: the facts of a host (its release, its support) have no source in the constellation, and the nodes and the hosts are Portarr's to say.
7. **The perimeter does not hide failures.** A repository of the description that cannot be read (not found, no access, a tree too large, files that could not be read, an answer that is not what the API documents) is shown on the table. A skip of a platform row ends only when the releases are known.
8. **The code is read in the background**, never inside a request for longer than a few seconds: a request that comes during a reading gets what was read last and the screens are told (the `problems` topic) when a new index is there; a refresh does not read again before a minute; a reading has a time budget. This adds nothing to the inventory of ADR 0002: Portarr still says what runs where, the description says what is maintained and in which code, and nothing of Portarr's data is copied (the identifiers of environments only point to Portarr's).

Amends nothing of [ADR 0002](0002-environment-description-is-a-provider.md): where each application runs stays Portarr's; the code that deploys it is policy (the maintainer's perimeter), not inventory.

## Consequences

- The maintainer decides, once and in one file, which repositories and which platforms are maintained; a repository of a training course on a personal account is simply absent.
- The same token reads repositories of an organisation and of a person.
- A repository must be on the forge to be in the perimeter; two infrastructure repositories of the maintainer are still on the work machine only.
- Reading costs one tree request per repository and one request per changed file (a file already read is not read again while its identifier is the same), kept five minutes.
- The pull request that applies a change is the next vertical: it needs a Runner task, the second factor, and the write power of ADR 0001.
- Not done here, on purpose: the last version of the current line before a major (the registry's tags are not in the fleet model yet), operating system support, Helm values, Terraform provider versions.
- The default branch of a repository is what is read, not the branch that is deployed; the two are the same for a repository that deploys from its default branch, and a different branch is for a later setting.
- The release channels of K3s are read by the host itself (`Platforms:K3sChannelsUrl`); a provider of its own comes when a second source of facts of that kind appears.
